# 运行配置、模型解析与多模态对话收口

日期：2026-08-05

版本：v0.1.2

范围：semantic-framework

## 为什么

原有配置模板、服务启动配置和前端设置写入位置彼此分离，导致安装后配置路径不明确；
同时，模型密钥更新、Agent 模型切换和会话 Runner 缓存之间缺少一致的失效规则，可能出现
页面配置与实际运行模型不一致。图片输入、运行中断以及服务商 reasoning 输出也存在兼容和
持久化缺口。本次变更先把单 Agent 对话基础链路做实，为后续 Skill、工具和多 Agent 设计提供
稳定运行基线。

## 主要内容

### 安装配置与配置路径

- 新增 `semantic init`，从内嵌模板生成安装配置；配置模板仅保留 mock 默认模型。
- 统一默认安装配置路径、显式 `-c` 启动路径与设置接口实际写入路径。
- `semantic doctor`、服务启动和热重载复用同一套路径解析规则。
- 设置接口返回当前配置文件位置与密钥来源，便于前端说明配置实际生效位置。

### 模型服务、密钥与运行模型

- 模型服务密钥按 provider 保存，支持环境变量与 SQLite 设置存储的来源优先级。
- LLM、Agent profile 或模型策略变化后，空闲会话 Runner 立即失效；运行中的 Runner 完成本轮
  后失效，保证单轮一致且下一轮采用新配置。
- run 元数据与 `message.done` 增加实际模型解析信息：请求端点、最终端点、model ID 和回退标记。
- 向运行时角色提示注入实际模型身份，避免模型根据训练身份或历史上下文错误自述。
- 默认配置删除真实模型与默认密钥，仅保留 mock；真实服务必须由用户配置后启用。

### 对话、推理与多模态

- 修复中断后产生空 assistant 历史消息而导致下一轮模型请求 400 的问题。
- 支持单轮 reasoning effort/visibility 覆盖，并持久化本轮实际推理策略。
- 增加跨流式分片的 `<think>` 解析，将服务商返回的思考内容归入 reasoning 事件；隐藏策略下不下发。
- 图片附件以模型多模态消息发送；移除不兼容 MiniMax 的 `image_url.detail=auto` 字段。
- Leader 与 SubAgent 的推理、工具和结果继续保留各自 Agent 归属，不把 SubAgent 工具累计为 Leader 工具。

### 接口、文档与测试

- 同步更新 REST、WebSocket、配置参考、服务架构与 README。
- 增加 init、配置路径、设置写入、热重载、模型切换、实际模型元数据、图片请求、reasoning 分流、
  中断恢复和 Team 集成测试。

## 配置与数据影响

- 配置模板仍是不可变安装源；运行期修改写入服务启动时解析出的实际配置文件。
- 设置密钥保存在 SQLite 的服务级 settings 表中，API、日志和审计输出均掩码；当前仍是明文落盘，
  后续需要引入系统密钥环或主密钥加密方案。
- 数据库迁移增加设置存储所需结构；既有数据库由启动迁移自动升级。
- `message.done.payload.model` 与 run metadata 的 `model` 为向后兼容的可选字段。

## 已知限制与后续

- 当前多 Agent 仍是协作机制原型；Robot Agent、Monitor、Team 生命周期和多人式输出需先确认职责。
- 标准 Skill 的 `scripts/` 沙箱执行与 `references/` 按需读取尚未落地。
- provider 密钥静态加密、真实服务连接诊断及多服务商人工验收仍需补齐。
- `internal/agent/runtime/service.go` 已超过建议行数，本次不阻塞交付，后续按运行编排、会话管理职责拆分。
